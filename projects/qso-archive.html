BA4THG 通联档案

这是 BA4THG 的独立 QSO 长期档案、公开查询和 QSL 卡片申请入口。日常通联仍然在现有工具中记录，本站负责把近期公开数据和自己的长期档案合并，并把旧记录持续保留下来。

正式域名
qso.mizuki.top
长期存储
Cloudflare D1
运行方式
Cloudflare Pages + Functions
01 / 为什么做

近期查询交给上游，长期档案由自己保存。

第三方公开接口适合提供当前能够查询到的近期记录，但它不是长期档案。这个项目把两者分开：用户主动按呼号查询时获取近期记录，经过校验和去重后写入 D1；已经进入 D1 的记录会作为长期档案保留。

第三方小程序日常记录
        │
        ▼

        ├─ 主动按呼号查询近期记录
        ├─ QSL 身份核验与申请

        └─ 校验 / 去重
               │
               ▼
        Cloudflare D1 长期档案
               │
               ▼
          qso.mizuki.top
02 / 数据原则

不是把数据库公开出来，而是只回答一个明确问题。

主动查询

首页默认不展示任何 QSO，访客需要主动输入对方呼号才会查询。

固定本台

本站固定以 BA4THG 为本台，只按对方呼号做精确匹配。

长期归档

已经同步或导入 D1 的记录不会因为上游以后不再返回而自动删除。

来源优先级

直接上游记录、本地人工修改和补齐数据有明确优先级，避免旧数据覆盖新数据。

还可以从历史文件直接进入

ADIF、CSV、JSON 和手工录入都可以进入长期档案，不要求所有历史记录都必须先经过第三方 API。

03 / QSL 与管理边界

公开查询和管理接口不是一个权限等级。

  • 公开页面只提供按呼号查询，不支持按地点、设备、频率、天线等条件扫描整个数据库。
  • QSL 申请按 lookup → 身份核验 → submit → status 的流程走第三方正式状态机。
  • 管理页面和 /api/admin/* 由 Cloudflare Access 统一保护。
  • 自定义域名、Pages 默认域名、WAF 与 Bot 规则需要分别处理浏览器与机器调用场景。
